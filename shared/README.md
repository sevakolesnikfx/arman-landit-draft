# Landit shared layer: API for the three designs

Everything a design needs about schemes, matching, content, words and the pretend chat lives in `window.LANDIT`. Designs never type a scheme, an amount, a phone number or the disclaimer themselves: they read it from here.

## 1. Loading

Load these four scripts, in this order, before your own code. Plain `<script>` tags work from `file://`, no server needed.

```html
<script src="../shared/data.js"></script>     <!-- GENERATED: catalog, icons, safety -->
<script src="../shared/match.js"></script>    <!-- matcher, sorting, money -->
<script src="../shared/content.js"></script>  <!-- questionnaire, demo, words, community -->
<script src="../shared/chat.js"></script>     <!-- the pretend chat -->
<script src="themes.js"></script>             <!-- your own themes (section 12) -->
```

`data.js` is generated by `node tools/build-data.mjs` from `shared/source/`. Never edit it by hand.

## 2. What every design must support (the tools test this)

| Thing | Contract |
|---|---|
| Routes (hash) | `#/login`, `#/register`, `#/questions`, `#/ack`, `#/chat`, `#/benefits`, `#/benefit/<id>`, `#/community`, `#/settings` |
| `?reset=1` | Clear everything this design saved, then open Register. |
| `?demo=1` | Sign in as `LANDIT.demo` (profile answered, two tracked schemes, disclaimer already acknowledged). |
| `?lang=<code>` | Interface language (`en pl ro ur ar uk`). Set `<html lang>` and `<html dir>` from `LANDIT.dir(code)`. |
| `?theme=<id>` | Use that theme from your `themes.js`. |
| `?text=xlarge` | Largest text size. |
| Disclaimer | `LANDIT.disclaimer`, word for word, visible on `#/ack`, `#/chat`, `#/benefits`, `#/benefit/<id>`, `#/community`, and in the footer. |
| Phone sidebar | The button that opens it needs an `aria-label` containing "menu", "sidebar", "navigation" or "applications". |
| Icon buttons | Always an `aria-label`. `LANDIT.icon()` output is `aria-hidden` unless you pass `label`. |

Params combine: `index.html?demo=1&lang=ar#/benefits`.

## 6. Benefits

`LANDIT.benefits` is an array of 182 schemes in catalog order. Fields:

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable id, use in routes: `#/benefit/council-tax-student` |
| `entry` | number | Position in the catalog (1 to 182). Tie-breaker for sorting. |
| `name` | string | Official scheme name. English in every language (it mirrors GOV.UK). |
| `sub` | string | One short line for cards. 81 were cut mid-word by the old generator and are trimmed back to a whole clause (`subTrimmed: true`). The cut is made before the plain-English rewording, so a few lines are now longer than 110 characters (longest 159). |
| `about` | string | Full description from the catalog, for the detail page, in plain English (section 13). |
| `category` | string | Key into `LANDIT.categories`. `categorySource` keeps the catalog's original key. |
| `region` | string | Catalog region text, e.g. `"England, Scotland, Wales"`, `"NI"`. `regionSource` keeps the original. |
| `regionLabel` | string | Plain label to show: `"Whole UK"`, `"England and Wales"`, `"London only"`, `"Depends on your council"`. |
| `nations` | string[] | Nations where it can apply. Used by the matcher. |
| `local` | string or null | Area inside England, e.g. `"London"`, `"Greater Manchester"`. |
| `publicFunds` | boolean | On the paragraph 6.2 public funds list. |
| `nrpf` | `'yes'`, `'no'`, `'depends'` | Can someone with no recourse to public funds get it in practice. Show `'depends'` as "It depends on your situation". |
| `nrpfNote` | string or null | Internal engine note in technical wording ("Universal Credit-gated: show only to..."). Not checked by the plain-English rules. **Do not show to users.** |
| `who` | string[] | Status keys, or `['all']`. `whoSource` keeps the original. |
| `closed` | boolean | Ended or suspended (2 schemes). Never open or blocked. |
| `value` | number or null | Amount in pounds. Only ever shown with `valueLabel`. |
| `valueLabel` | string or null | Qualifier for `value` ("Typical annual saving", "Up to, one-off", "Could be worth, a year"), or a description when there is no amount ("£123.25 per week", "Free care"). Null when the catalog has nothing sourced. |
| `valueKind` | `'amount'`, `'label'`, `'none'` | 32 amount, 29 label, 121 none. For `none`, show nothing or "No set amount". Never write "Free" yourself. |
| `valueNote` | string or null | Detail behind the amount, for the detail page. |
| `statRate` | number or null | A real published approval rate (0 to 1). When null, show `LANDIT.noRateText`. Never invent one. |
| `stat` | string or null | What the published figure says, with its source. |
| `rules` | string[] | Plain conditions from the catalog. Lifetime ISA also has "Age 18 to 39", moved here from its document list (section 13). |
| `applyUrl` | string or null | Official page (146 have one). |
| `sources` | string[] | Source URLs. |
| `strengthen`, `note` | string or null | Extra tips from the catalog. |
| `guide` | object | See below. |
| `docs` | object[] | What to gather. See below. |
| `docsKnown` | boolean | True when a hand-written guide lists what to gather (58 schemes). When false, `docs` only holds hints and the honest message is "check the official page". |
| `docsCount`, `stepsCount` | number | `docs.length`, `guide.steps.length`. |
| `timeMinutes` | number or null | Conservative lower bound of `guide.time` in minutes, for sorting only (46 known). "2 to 4 hours" gives 120, "Nothing to do" gives 0, "One conversation" gives null. Show `guide.time`, never this number. |
| `effort` | `'low'`, `'medium'`, `'high'` or null | Landit's own estimate, only for the 58 hand-written guides. Show `effortLabel` with `LANDIT.effortNote`. |
| `effortLabel` | string or null | `'Quick and simple'`, `'Some paperwork'`, `'More paperwork'`. |

**Effort thresholds** (in `tools/build-data.mjs`): `low` when docs 1 or fewer and steps 4 or fewer; `high` when docs 4 or more, or steps 6 or more; otherwise `medium`. Docs counts every item in `docs` (needed and maybe). Today: 13 low, 27 medium, 18 high, 124 null. (Before the document fixes in section 13 it was 12, 27, 19: Lifetime ISA went from high to medium, Help to Save from medium to low.)

**`guide`**: `{time, decision, cost, steps[], boost[], watch, needNote, generic}`

- Hand-written (58): `time` ("20 minutes"), `decision` ("2 to 6 weeks"), `cost` ("Free", "£35 for the year"), `steps` (in order), `boost` (how to improve the chances), `watch` (the most common mistake), `needNote` (for example "Nothing is legally required" when there is nothing to gather), `generic: false`.
- Generic (124): the prototype's fallback guide built from the catalog. `time`, `decision`, `cost` are null (unknown, do not show "Free"), `generic: true`. Label these guides as general steps.

**`docs`**: `[{id, label, certainty, from}]`

- `label`: original wording from the guide or catalog, with abbreviations spelled out (section 13).
- `certainty`: `'needed'`, or `'maybe'` for items that only apply sometimes (they start with "If", "For", "Where", "When", or contain "if you", "if relevant", "for a non-working...") and for catalog and rule hints. Exception: a hint the scheme's own rule or guide requires is `'needed'` (`DOC_FIX.REQUIRED`: the food bank referral voucher).
- `from`: `'guide'` (hand-written list), `'catalog'` (the catalog's document gate, e.g. "Tenancy agreement"), `'rule'` (a catalog rule naming proof, e.g. the food bank referral voucher).
- `id`: stable within the scheme, used for ticks: `'your-tenancy-agreement'`. Made from the label before abbreviations are spelled out, so ids do not change when wording does.
- Conditions are not documents: "Age 18 to 39" (Lifetime ISA), "A Universal Credit claim with £1+ of earnings that month" (Help to Save) and "A frontline professional willing to apply for you" (Buttle UK) are left out of `docs` (`DOC_FIX.NOT_A_DOCUMENT`); each is in that scheme's `rules`.

Example (trimmed):

```js
LANDIT.benefitById('council-tax-student')
{ id: 'council-tax-student', name: 'Council Tax student exemption (Class N)',
  sub: '100% off for student households', category: 'council', regionLabel: 'England, Scotland and Wales',
  publicFunds: false, nrpf: 'yes', who: ['student', 'graduate'],
  value: 1800, valueLabel: 'Typical annual saving', valueKind: 'amount',
  guide: { time: '20 minutes', decision: '2 to 6 weeks', cost: 'Free', steps: [5 steps], boost: [3], watch: '...', generic: false },
  docs: [ { id: 'student-certificate-from-your-university-free', certainty: 'needed', ... },
          { id: 'your-tenancy-agreement', certainty: 'needed', ... },
          { id: 'share-code-for-a-non-working', certainty: 'maybe', ... } ],
  docsKnown: true, timeMinutes: 20, effort: 'medium', effortLabel: 'Some paperwork' }
```

## 7. Matching

### `LANDIT.match(profile)`

Profile (all keys optional; the questionnaire values in section 9):

```js
{ status: 'student',        // a status key, 'unsure', or missing
  nation: 'England',        // a nation key; missing means England is assumed
  work: 'not_working',      // 'employed' | 'self_employed' | 'not_working'
  study: 'full_time',       // 'full_time' | 'part_time' | 'not_studying'
  children: 'no',           // 'yes' | 'expecting' | 'no'
  housing: 'rent',          // 'rent' | 'own' | 'family' | 'other' (not used by the matcher)
  age: '16_25',             // '16_25' | '26_59' | '60_plus' | 'no_say'
  // optional, never asked by the questionnaire:
  nrpf: true,               // overrides the status default
  city: 'London', partner: true, carer: false, disabled: false, pregnant: false }
```

Result:

```js
{ open: [benefit],                 // may be able to get it; sorted by value, largest first
  blocked: [{ benefit, reason, kind }],   // kind 'public-fund' or 'needs-public-fund'
  fit: { 'railcard-16-25': 'confirmed', 'council-tax-student': 'possible', ... },  // one per open id
  total: 6464,                     // sum of open values: show ONLY with totalLabel
  totalLabel: 'Potential, if all approved',
  withValue: 7,                    // open schemes that have an amount
  status: 'student', statusLabel: 'Student visa',
  known: true,                     // false when there is no status
  nrpf: true,                      // null when status unknown
  nation: 'England', nationAssumed: false }
```

Blocked reasons, word for word:

- `public-fund`: "This is a public fund. Your visa has a no recourse to public funds condition, so this one is not open to you."
- `needs-public-fund`: "This is not a public fund itself. But people with a no recourse to public funds condition cannot get it in practice, usually because it needs a qualifying benefit."

How it decides (port of the prototype engine):

1. `closed` schemes are left out.
2. Life situation (the prototype's table of 68 schemes): a scheme is hidden only when an answer rules it out. Unanswered means shown.
3. Nation: hidden when `nations` does not include the person's nation. London-only schemes are hidden only when `city` is known and is not London.
4. With no status: open = schemes for everyone (`who` has `all`) that are not gated. Nothing is blocked, `known: false`.
5. Gated = `publicFunds` or `nrpf: 'no'`. Gated and the person has NRPF: **blocked**, whatever `who` says (as in the prototype: the visa condition is the reason).
6. Otherwise open when `who` has `all` or the status; hidden when not.

What each answer is used for:

| Answer | Used for |
|---|---|
| `status` | `who` lists; NRPF from `nrpfDefault` |
| `nation` | `nations` |
| `work` | employed: Statutory Sick Pay, workplace pension, New Style JSA and ESA. Not working: Smart Works, interview clothing, Timpson dry cleaning |
| `study` | full time: university hardship fund, Student Oyster, 16-25 Railcard (with age) |
| `children` | 38 schemes about children or pregnancy (school meals, childcare, Child Benefit, baby banks...). `expecting` counts as pregnant: maternity schemes, Healthy Start, baby box |
| `age` | bands against age limits: Railcard (25 or under), King's Trust (16 to 30), Lifetime ISA (18 to 39), under-22 bus (Scotland), EMA (16 to 18), 16 to 19 Bursary, Youth Guarantee (18 to 21), Job Start Payment (16 to 24), State Pension age schemes (66 or over). A band that only partly overlaps a limit counts as unknown, so the scheme stays. |
| `housing` | Not used: no catalog rule depends on it. Kept for Settings and the chat. |

Demo profile result: **79 open, 13 blocked**, total **£6,464** potential, 7 with an amount, **17 confirmed and 62 possible**. (Before the Free Courses for Jobs correction in section 13 it was 80 open and £8,464.)

### Certainty: `fit`, `fitLabel`, `rankForHighlights`

`match(profile).fit` gives every open scheme one of two values. It never changes what is open or blocked.

- `'confirmed'`: the answers meet every rule the matcher checks, and the catalog states no other condition. Example for the demo: 16-25 Railcard (age 16 to 25 answered), GP registration, National Insurance number.
- `'possible'`: something is not known. Any one of these makes a scheme possible:
  - the catalog says `nrpf: 'depends'`;
  - a life-situation rule (the table above) that the answers do not confirm, for example Marriage Allowance when no partner was asked about, or Maternity Allowance for a parent who did not say "expecting";
  - the nation was not answered (England assumed) and the scheme is not in all four nations;
  - the scheme is only in part of a nation (a city, council, provider or postcode area);
  - the catalog names a condition the questionnaire does not ask: income or savings, a partner, who lives with you, disability or health, caring, a child's age or school, a crisis, years of residence, an employer or earnings. Example for the demo: Council Tax student exemption ("All occupants students or disregarded"), British Gas Energy Trust (income and energy debt), University hardship fund (a shortfall).

How it is decided: `CONFIRMABLE` in `match.js` lists the 30 schemes whose catalog conditions are fully covered by the answers, each with the catalog words that justify it. Every other scheme is always `'possible'`. This is conservative on purpose: a wrong "possible" only adds a label, a wrong "confirmed" would read as a promise.

```js
LANDIT.fitLabel              // { possible: 'Depends on your situation' }: show it on every 'possible' scheme you highlight
LANDIT.rankForHighlights(list, m.fit)
// Confirmed first, then possible; each group keeps the order it came in.
// Sort first, then rank. Use it for any headline pick:
LANDIT.rankForHighlights(LANDIT.sortBenefits(m.open, 'time'), m.fit)[0]    // "Quickest to apply"
LANDIT.rankForHighlights(LANDIT.sortBenefits(m.open, 'value'), m.fit)      // "Highest amount"
// Accepts benefits or {benefit} items; `fit` may be m.fit or m itself.
// A blocked item has no fit and counts as possible (order unchanged).
LANDIT._certainty(id, profile)   // { fit, why: ['unasked', 'situation', ...] } for tests only, never shown
```

For the demo: "Quickest to apply" is now the 16-25 Railcard (10 minutes, confirmed), not Marriage Allowance (possible: never asked about a partner). "Highest amount" is the Railcard (£212, confirmed) ahead of Council Tax student exemption (£1,800, possible), if a design ranks with `rankForHighlights`. Lists sorted by the person (the Benefits page sort control) should keep using `sortBenefits` alone.

### Helpers

```js
LANDIT.sortBenefits(list, 'value' | 'time' | 'docs' | 'az')
// value: largest first. time: quickest (timeMinutes) first. docs: fewest first,
// schemes without a hand-written guide count as unknown. az: by name.
// Unknown values always last; ties keep catalog order. Works on blocked items too.
LANDIT.formatMoney(1800)   // '£1,800'
LANDIT.formatMoney(12.5)   // '£12.50'
LANDIT.formatMoney(null)   // null
LANDIT.valueParts(b)       // { amount: '£1,800', label: 'Typical annual saving' } (amount null when none)
LANDIT.benefitById(id)     // benefit or null
LANDIT.statusLabel('student')  // 'Student visa'
LANDIT.searchBenefits(list, 'rail card')  // every word in name, sub or category label
```

## 8. Safety ("Help now")

`LANDIT.safety[nation]` is a list of groups for that nation: `[{key, group, icon, items: [{id, label, number, tel, note, url}]}]`. Seven groups: emergency, police, health, scams, abuse, children, home. `tel` is digits for a `tel:` link (null when there is nothing to dial). `url` is set only where the source names a website. ## 9. Content (`content.js`)

**`LANDIT.questionnaire`**: 7 questions, all skippable, in this order: `status`, `nation`, `work`, `study`, `children`, `housing`, `age`. Each `{id, question, help, icon, options: [{value, label, icon?}]}`. The `id` is the profile key and `value` is what to store. `status` options are the 11 statuses plus `{value: 'unsure', label: 'Not sure'}`.

`LANDIT.answerLabel(questionId, value)` gives the readable answer for Settings: `answerLabel('age', '16_25')` is `'16 to 25'`.

`LANDIT.statusPhrase(key)` starts a sentence about a status: `'On a Student visa'`, `'With refugee status or humanitarian protection'`, `'While you wait for an asylum decision'`. Use it for lines like "On a Student visa in England, you may be able to get 79 schemes".

**`LANDIT.trackStatuses`**: `[{value: 'Not started', i18n: 'st_not_started'}, 'Applied', 'Approved', 'Turned down']`. Store the `value`; show `LANDIT.t(i18n, lang)`.

## 10. Chat (`chat.js`)

```js
LANDIT.chatReply(text, { profile, name, lang, tracked })
// -> { paragraphs: [1 to 3 strings], benefitIds: [ids to show as cards],
//      suggestions: [2 to 4 follow-up questions], action?: 'help-now' }
LANDIT.chatStarters(profile)          // 4 to 6 suggestion strings
LANDIT.chatGreeting('Amara', hour, lang)   // 'Good morning, Amara' (uses greet_* translations)
```

- `tracked` has the same shape as `LANDIT.demo.tracked`.
- When `action` is `'help-now'`, show the Help now panel or a clear button to it.
- Show `benefitIds` as small cards linking to `#/benefit/<id>`.
- Suggestions are meant to be sent back as the next message. They always route to an answer.
- Replies use these interface words, so use the same ones in your UI: **Benefits**, **Settings**, **Help now**, **Track**, **sidebar**.
- Top picks ("What can I claim?", topic answers, the first scheme for "which documents") use the matcher's certainty: confirmed schemes first, then possible ones (inside the possible group, a life-situation rule the answers did not confirm goes last, then catalog "depends" schemes).
- **Every** reply that names an open scheme whose `m.fit` is `'possible'` says so: "It depends on your situation, so check the details first." for one scheme, "Some of these depend on your situation, so check the details first." for a list. That covers a single scheme, "What can I claim?", topics, council tax (the "Council tax as a student" reply now has it), which documents, tracking, and the free advice line in the no recourse answer. Blocked and hidden schemes never get it.
- The person's list is called **benefits** in replies, as in the designs: "you may be able to get 79 benefits", "Landit set aside 13 benefits that are public funds or need one", "Here are 3 of 8 benefits for health". "Scheme" stays only for one named scheme or the general rule ("If a scheme is not on that list...").
- Understands (with typos): what can I claim; a scheme by name or short name (railcard, oyster, hardship fund, GP, council tax reduction, food bank...); which documents do I need; travel, health, bills, childcare, food; **learning English** ("english classes", "ESOL", "learn English", "language course", typos such as "englsh clases" or "inglish": Free ESOL courses, Free English conversation clubs and Public libraries, with a line on why ESOL is not shown when it is not open); council tax; no recourse to public funds; how tracking works; urgent help (danger, abuse, emergency: exact words only, so "policy" never reads as "police"); hello, thanks, what can you do. Anything else gets a friendly fallback with suggestions.
- Typos, not other words: a word that is spelled correctly is never read as a one-letter-off keyword. Every word of 4 or more letters in the shown catalog text, plus a list of everyday words found by testing (`NOT_TYPOS` in `chat.js`), only matches exactly. Before, "english classes" read as "glasses" (health), "free english course" as "recourse" (the no recourse answer), "lerning english" and "earnings" as NHS Learning Support Fund, "later" as "water" (bills), "think" as "thank", "means tested" as "meals" (food), "eating" as "heating" (bills). Endings still match ("dentists", "doctors"). "learning" alone no longer picks NHS Learning Support Fund; ask for it by name or "learning support fund".
- No network, no AI. English only. Replies take a moment to write in a real product: add a short typing delay if you like.

Demo starters: "What can I claim?", "Council tax as a student", "What does no recourse to public funds mean?", "Help with travel costs", "Help with bills".

## 11. Rules for every design

- No en dash or em dash characters anywhere, including comments and HTML entities.
- Never type an amount, a phone number, a scheme fact or the disclaimer. Read them from `LANDIT`.
- An amount always travels with its qualifier (`valueParts`). A total is always labelled `LANDIT.potentialLabel`.
- Say "you may be able to", never promise. No gamification: no points, no rating symbols, no game words (the checker lists the banned words in `tools/content-rules.mjs`).
- "Student visa", "Landit". No founders' nationality, no parent company name.
- Nothing about Landit's cost except `LANDIT.freeLabel`.
- Right to left: scheme names and catalog text stay English inside Arabic or Urdu pages. Wrap them in `<bdi>` or give their element `dir="auto"`, or "16-25 Railcard" renders as "Railcard 16-25".
- Do not show `nrpfNote` to users. Show `nrpf: 'depends'` as "It depends on your situation".
- When a scheme is highlighted (a "Highest amount" or "Quickest to apply" tile, a first suggestion), pick it with `rankForHighlights` and show `LANDIT.fitLabel.possible` on it when `m.fit[id] === 'possible'`.

## 13. What the build changed in the catalog, and why

All changes live in tables at the top of `tools/build-data.mjs`, with the reason next to each. Originals are kept (`categorySource`, `regionSource`, `whoSource`).

- **Wording**: a few catalog figures of speech used words Landit bans. They were swapped for plain words with the same meaning ("opens" for the old verb, "your pension savings", "a duty to everyone", "no placement test"). The old visa route name became "Student visa". Qualification names ("Level 3", "A-level") stay.
- **Categories (20)**: the old generator filed some schemes under the wrong key (Scottish Welfare Fund and Local welfare assistance under transport, disability benefits under money). Each now matches its section in the catalog.
- **Regions (11)**: five Scottish benefits (Adult Disability Payment, Child Disability Payment, Carer Support Payment, Job Start Payment, Funeral Support Payment) were marked "UK", and four England schemes too. Home fee status covers all four nations.
- **Who (7)**: schemes with no "who" line defaulted to everyone, so a Student saw the Ukraine Permission Extension. Fixed only where the scheme's own name or text names the group, plus Free Courses for Jobs (below).
- **Free Courses for Jobs, Student visa removed**: it showed as the demo's highest open amount ("Could be worth £2,000"). Its entry (139) says it uses "Standard adult skills residency", and entry 15 (Free ESOL courses) says "sponsored Skilled Worker and Student visas are excluded from adult skills funding". Its `who` is now every status except `student` (was `all`). Effects: not shown to Student visa holders, and no longer shown when the visa is not answered or "Not sure" (it is no longer "for everyone"). Skilled Worker is kept because entry 139 says "most visa holders ... after 3 years residence"; that conflicts with entry 15 for sponsored workers and needs a person to check. Not changed: Free ESOL courses (already excludes Student and Skilled Worker), Skills Bootcamps (entry 140 gives apprenticeship-style residency, nothing about Student visas; it shows as "possible"), Advanced Learner Loan and Postgraduate loans (student finance, not adult skills funding; both "possible"). There is no Multiply entry in the catalog.
- **Plain English (248 rules, 135 schemes)**: the `PLAIN` table in `tools/build-data.mjs`, one row per rule with its reason. Three kinds:
  - INTERNAL (a note to the app or an editorial label, not a fact): removed or replaced by the neutral fact. "(Scotland and Wales entries: 146 and 157.)", "before building copy on it", ": blocked" in the Discretionary Support (NI) name, "worth surfacing" (nrpfNote only), "flagship" (now "main"), "in this catalog" (now "in Landit's list"), "The killer detail:", "designed floor" (now "safety net designed for"), "master gate" (now "main test"), "parallel system" (now "separate support system"), "The race:" (now "Watch the timing:"), "NRPF-safe sibling", "entry-30 partner rule" (now "the Tax-Free Childcare partner rule").
  - PLAIN (a fact in technical words, same meaning): "NRPF-safe" as "open to people with no recourse to public funds", "NRPF" spelled out phrase by phrase ("NRPF families" as "families with no recourse to public funds", "closed under NRPF" as "not open to people with no recourse to public funds"), "Composition-based" as "Based on who lives in the home", "Contribution-based"/"contributory" as "based on National Insurance (you have paid)", "benefit-gated"/"Gated on" as "needs a qualifying benefit"/"Only for people getting", "passports to" as "qualifies you for", "means-tested" as "based on income and savings" and "not means-tested"/"no means test" as "no check on income or savings", "recourse" alone as "recourse to public funds", and the abbreviations UC, HP, ILR, EUSS, FSM, HRT, CRF, HSF, DHPs, WHD, LCWRA, HICBC, ADG, IAP, EAP, NINo, ADP, AA, DLA, NI (National Insurance only) and s1/s3C/s17/s95/s98/s4/s179/s13A (as "section ...").
  - ABBR (86 rules, 100 schemes): abbreviations and short forms a reader with basic English may not know, in every shown text field **except names** (official names stay as published: "Lifetime ISA", "New Style ESA", "EMA Wales", "NHS Low Income Scheme (HC2/HC3)", "ECO4 and LA Flex", "NI Childcare Subsidy Scheme"). Most use "Full words (ABBR)" at the first use in each field, only the full words inside brackets: PPC as "prescription prepayment certificate (PPC)", IHS as "Immigration Health Surcharge (IHS)", ARC as "Application Registration Card (ARC)", BRP as "biometric residence permit (BRP)", A&E, FGM, PIP, ESA, JSA, SMP, SSP (spelled out in text, kept in names), APR, PAYE, EPC, HGV, NEET, RQF, D&T, PE, GBIS, LA Flex, ECO and ECO4 (Energy Company Obligation), and the bodies and charities DfE, NHSBSA, UKHSA, SLC, MoJ, TfL, TfGM, CCW, BGET, JCWI, ICIBI, NASS, ASAP (Asylum Support Appeals Project, which read like "as soon as possible"), STAR, OISC. Fully replaced: LISA as "Lifetime ISA", GM, WM, UU, GB, CR (City Region), NLW, SFE, CA, NIHE, "NI" as "Northern Ireland" (except the names "Law Centre NI" and "Welfare Reform (NI) Order"), Q1 2026 as "January to March 2026", P1 to P5 and P6 (Scottish primary years), EEA, FAQ, CPI. Short forms: "/yr" as "a year", "hrs/week" and "h/week" as "hours a week", "/wk", "/hr", "~" as "about", "e.g.", "incl.", "para", "max", "£100k" as "£100,000", "£15bn" as "£15 billion", "2.6m" as "2.6 million", and the months Jan, Feb, Aug, Sept. Same meaning: no fact added, none dropped. Document ids are made before this step, so ticks still match.
  - Kept on purpose (listed at `ABBR_EXPLAINED` in the script): "NRPF Network" (an organisation), form and certificate names (HC1, HC2, HC3, HC5, MATB1, SMP1, SSP1, MA1, SF100, FW8, CH2, GMS1, ASF1, P45, P50, P85, P800), tax codes (1257L, W1/M1, BR, 0T), bodies people deal with directly (DWP, HMRC, NHS, HM Treasury, GOV.UK), company and brand names (BT, EE, O2, SMARTY, VOXI, KCOM, EDF, OVO, HSBC, NatWest, BBC, TOTUM, UNiDAYS), vaccine names (MMR, MenACWY), words most people know (UK, EU, GP, ID, TV, CV, SIM, TB, HIV), the status name BN(O), Appendix FM, document references (MD3509, CBP-10827), "ECO4 LA Flex" as the words to search for on a council site (explained in the same step), abbreviations the same field already explains (IAA, ECF, SWEP), a quotation ("the HAF programme is not a public fund"), and source notes such as "(verified)".

The generic guide's lines were reworded the same way ("This one is safe with a no recourse to public funds condition" is now "A no recourse to public funds condition does not stop you getting this").
  - Chat: because names now spell out "no recourse to public funds", the words "no", "recourse" and "public" no longer pick a scheme by name, so "What does no recourse to public funds mean?" still gets the explanation.
- **Documents (5 fixes, `DOC_FIX` in the script)**: every guide need list, catalog document gate and rule-based document was read against its scheme's own rules and guide. Two kinds of error, nothing invented:
  - A condition listed as a document. - **Closed (2)**: Free bus for asylum seekers (pilot ended), Refugee family reunion (suspended).
- **Value labels**: 121 parsed schemes carried a default "Free" label, including loans and paid services. Removed (null). National Insurance number shows "Free" (from its guide) instead of "Enabler".
- **Short lines**: 81 cut-off `sub` lines trimmed back to whole clauses. Internal cross-references ("(entry 66)") and one note to the app were removed from `about`.
- **Nations**: "NI" now means Northern Ireland and "GB" excludes it; notes in brackets ("abolished in England") no longer count as a nation.
- The guide for `single-person-discount` has no catalog entry, so 58 schemes have hand-written guides (not 59).

## 14. Open data questions

Found while checking the catalog. None of these facts was changed: each needs a person to check the source.

- **Free Courses for Jobs and Skilled Worker visas.** Entry 139 (this scheme) says "most visa holders and EU Settlement Scheme after 3 years residence". Entry 15 (Free ESOL courses) says "sponsored Skilled Worker and Student visas are excluded from adult skills funding". The build removed the Student visa only (section 13), so a Skilled Worker or Health and Care visa still sees Free Courses for Jobs as possible.
- **Postgraduate loans.** Its own text says "work/study visas excluded", but its `who` is everyone (`all`), so it is open (possible) for every status, including the demo Student visa.
- **Advanced Learner Loan.** Its engine note says "same categories as student finance", and student finance excludes work and study visas, but its `who` is everyone (`all`), so it is open (possible) for every status. Its region also reads "Whole UK"; worth checking with the same source.
- **MyTravelPass Wales.** The text says "through 31 August 2026 it means £1 single and £3 day tickets" and "check whether it is extended past 31 August 2026". That date has passed (today is 1 October 2026), so the text needs the current position.
- **England bus fare cap.** "£3 to 31 December 2026, then £2 for the whole of 2027" (announced 22 July 2026). Expected to move: check before each release.
- **ECO4.** The Warm Homes guide says "The Energy Company Obligation (ECO4) runs only to 31 December 2026". Expected to change: check before each release, together with the "ECO4 and LA Flex" entry.
